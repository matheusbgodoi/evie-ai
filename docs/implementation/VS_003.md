# VS-003 — Identity, window control, and the animated mark

Last updated: 2026-08-05

This slice turns the working prototype into something that reads as *Evie's own
product* rather than a front end for a local inference server, and gives the user
direct control over where the overlay lives on screen.

It is the first slice driven entirely by the user's own review of the running
application. Everything below traces back to a specific complaint or request; the
requests that this slice does not implement are recorded in
[the follow-on plan](#follow-on-slices) rather than dropped.

## What shipped

### Identity

`EviePersona` in `EvieCore` generates the hidden system message from a capability
snapshot. Two properties matter:

- **The user is named.** Evie is told that Matheus Barboza de Godoi created her,
  that she addresses him as `você`/`seu`, and that every agreement is masculine.
  She is explicitly told never to call him "usuário" or speak about him in the
  third person.
- **She can only claim what is switched on.** `EvieCapabilitySnapshot` starts with
  every flag `false`. The prompt lists what she can do and states plainly what she
  cannot, so the moment microphone or file access exists, one flag flips and the
  wording follows. There is no way to describe a capability in prose and forget to
  build it.

The generated prompt can be inspected without launching a window:

```bash
./.build/release/evie-shell --print-persona
```

Verified against the running model on 2026-08-05:

> **Quem é você e quem me criou?**
> Eu sou a Evie e você me criou, Matheus.
>
> **Você consegue abrir minha pasta de Downloads?**
> Essa parte ainda não está ligada, Matheus, mas posso te ajudar com qualquer
> texto que você copiar e colar aqui.

### The interface no longer mentions the backend

`Gemma`, `TurboFieldfare`, and `127.0.0.1:port` are gone from every surface the
user sees: the entry field, the capsule, the status text, the error cards, the
menu-bar item, and the settings window. What remains is "Evie · assistente
pessoal" and, where a source label is genuinely useful, "Modelo local".

The raw endpoint is still reachable through
`OverlayViewModel.diagnosticEndpointDescription` for the diagnostics section of
Settings. It is a debugging value, not a product one.

### A port that will not collide

The default endpoint moved from `8080` to **`38433`**.

- `8080` is the single most contested port on a developer machine.
- `38433` is not in `/etc/services`, is not registered with IANA, and sits below
  `49152`, so macOS will never hand it out as an ephemeral source port for an
  outgoing connection. A port inside the ephemeral range can be stolen by an
  unrelated process between two launches; this one cannot.
- It is memorable: `EVIE` on a phone keypad is `3843`.

`Scripts/evie-runtime`, `.env.example`, and both configuration examples moved with
it. An existing local `config.json` keeps whatever it already had — the file wins
over the built-in default — so a running installation is migrated by editing that
one value.

### The window obeys

`EvieOverlayGeometry` in `EvieCore` resolves the panel rectangle from the saved
preferences plus the connected displays. Keeping it out of AppKit means display
disconnection, clamping, and resize behaviour are covered by tests rather than
discovered by dragging a window around.

- **Move**: a grip at the top of the overlay hands the mouse to AppKit's own
  `performDrag(with:)`. Multi-display travel, momentum, and Spaces behave exactly
  like a normal titlebar, and the panel never becomes key just because it moved.
- **Resize**: thin handles on both edges change the width around the window's own
  centre, clamped to 420–1200 points and to the display.
- **Reset**: a button appears next to the grip *only* once the placement differs
  from the default, and restores bottom-centre at 576 points.
- **Recovery**: a saved position is reused only when at least 160×48 points of it
  land on a connected display. Unplug the external monitor Evie was living on and
  she returns to the anchored default instead of opening off screen.

Geometry is written to `preferences.json`, a separate file from `config.json`, so
moving the window never rewrites the inference settings and vice versa.

### The fade is no longer cut

Three separate causes, all fixed:

1. **The panel guessed its own height.** It estimated `cards × 118 + expanded × 92`
   and clamped at 620. Whenever the guess was short, the content was clipped
   mid-gradient. The SwiftUI root now measures itself with `onGeometryChange` and
   reports the real height; the panel follows it. `fixedSize(vertical:)` on the
   root keeps that measurement independent of the height the window proposes, so
   there is no oscillation.
2. **The mask had no room to fade.** Its first stop was at 2.5% of the height,
   which reads as a hard edge. It now fades over 13% at the top and 6% at the
   bottom.
3. **The mask was always applied.** It now applies only when the list actually
   overflows; otherwise the top card was being faded for no reason.

### The mark

The inert circle in the entry field is now Evie's logo and her voice button.

**The art** is a key drawn on a character grid, in three densities. A monospaced
glyph cell is about 1.9× taller than wide, so stacked `Text` rows stretch the
drawing; the grid is rendered into a `Canvas` with explicitly square cells
instead. Measured legibility decides which grid is used: 5×5 up to 44 points, 7×7
up to 56, 9×9 above that. A 9×9 grid inside a 28-point badge works out to a
3.4-point font and is simply illegible.

**The motion is two layers, and the split is the whole point.**

| Layer | What it does | When | Cost |
|---|---|---|---|
| Tilt | `rotation3DEffect` with perspective, animated by Core Animation | Whenever the overlay is on screen | Effectively free — the render server interpolates the transform without re-running the view body |
| Light sweep | The ramp `" .:-=+*#%@"` re-chosen per cell per frame inside the `Canvas` | Only while listening, speaking, transcribing, thinking, or using a tool | One redraw per frame |

Measured on this Mac, release build, overlay visible and idle:

| Version | Idle CPU |
|---|---|
| First attempt: `Canvas` + `context.resolve(Text:)` per glyph, 30 fps | **8.1%** |
| Cached canvas symbols, 12 fps | 3.2% |
| Cached canvas symbols, 8 fps | 3.0% |
| **Shipped: transform tilt only when idle, sweep reserved for activity** | **0.0%** |

Two findings behind those numbers, both worth remembering:

- `context.resolve(Text:)` re-runs text shaping on every call. Declaring the ramp
  through the `Canvas(symbols:)` overload rasterises the ten glyphs once and
  reuses them; it is worth roughly 6× on its own.
- **`panel.orderOut(nil)` does not stop a SwiftUI timeline.** A hidden overlay
  measured 55 frames per second and 2.5% of a core, invisibly. Neither
  `.opacity(0)`, `.hidden()`, `alphaValue = 0`, nor `setIsVisible(false)` stops it
  either. Only removing the `TimelineView` from the view tree does. The motion
  gate is therefore lowered *before* `orderOut`, and window occlusion is observed
  as well, so a window dropped on top of the overlay also stops it.

**The colours were wrong and are now measured.** The previous listening tint
(`.mint`) resolves to 1.82:1 against the HUD surface in light mode — far below the
3:1 that WCAG requires for a graphical object, which made "listening" nearly
invisible on a light desktop. The shipped pair clears 4.5:1 in both appearances:

| Role | Light | Dark |
|---|---|---|
| Your voice going in | `#0D7770` | `#17CFC2` |
| Evie's voice coming out | `#7149E9` | `#9577EE` |

They resolve through `NSColor(name:dynamicProvider:)`, so they stay correct inside
the vibrancy view and when Increase Contrast changes the effective appearance.

Colour is not the only channel. Teal and violet both drift towards blue under the
common colour-vision differences, so direction is encoded geometrically as well:
**incoming audio grows inward** with 44 thin bars, **outgoing audio grows
outward** with 22 thick ones.

### Preferences

`EviePreferences` covers appearance, shortcuts, and voice. It is stored separately
from the model configuration, validates before writing, and repairs rather than
discards a damaged file. A future schema version resolves to defaults instead of
failing, because losing a preference must never make Evie unreachable.

Eight shortcut actions are modelled with defaults, conflict detection, per-action
disable, and reset. A binding must carry ⌘, ⌥, or ⌃ — shift alone only changes a
character, so a global registration on it would swallow ordinary typing.

**The voice dependency the user asked for is enforced in the type, not the UI.**
Call mode means "only the mark and its waves, no text at all". A call with no
voice would be a blank circle, so:

- turning speech **off** also leaves call mode;
- turning call mode **on** turns speech on;
- `validate()` rejects the inconsistent pair, so it can never be written to disk.

`EvieVoicePreferences.presentation` derives the three real states from those two
switches: `textOnly`, `textAndSpeech`, `call`.

## Toolchain constraint discovered

This Mac has the macOS Command Line Tools without full Xcode. In the macOS 26+ SDK
**`@State` is a macro**, and its plugin ships only with Xcode:

```
error: external macro implementation type 'SwiftUIMacros.StateMacro'
       could not be found for macro 'State()'
```

`@Environment`, `@Binding`, `@FocusState`, `@ObservedObject`, `@StateObject`, and
`@Published` all compile normally — only `@State` is affected. There is also no
Metal toolchain, so `.colorEffect`/`.layerEffect` with a custom shader are out.

The repository happened to contain zero `@State` before this slice, which is why
nobody had hit it. It is now a rule in `AGENTS.md`: transient view state lives in
an observable object. `OverlayChromeModel` holds the overlay's share of it.
