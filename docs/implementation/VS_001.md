# VS-001: native quick-text vertical slice

Historical boundary note: [VS-002](VS_002.md) supersedes the one-turn/process-memory
UI behavior with continuous input, local visible-history sessions, and model
settings. The direct loopback/no-tools boundary described here still applies.

Status: source and adjacent first-test runtime implemented on 2026-08-04;
target-hardware UI acceptance remains deferred to `QA-001`.

## What this slice proves

VS-001 is the first reversible end-to-end Evie path. It provides a native macOS
menu-bar process, transient glass overlay, quick-text entry, a backend-neutral
event contract, and streaming text from a separately managed local TurboFieldfare
server into an expandable result card.

The application does **not** install, download, start, stop, or supervise
TurboFieldfare or its model. Adjacent development scripts now perform explicit
first-test setup/lifecycle outside the application; they are not the future
supervisor. The slice still does not contain Hermes, tools, web search, RAG,
microphone capture, STT, TTS, OmniVoice, credentials, personal data, or persistent
history.

## Source map

- `Package.swift` declares the `EvieCore` library and `evie-shell` executable.
- `Sources/EvieCore/` contains backend-neutral messages, phases, artifacts,
  configuration, state reduction, and the streaming Chat Completions adapter.
- `Sources/EvieCore/EvieConfigurationLoader.swift` resolves non-secret model
  settings from defaults, a versioned local JSON file, then environment overrides.
- `Sources/EvieShell/AppCoordinator.swift` composes the temporary direct adapter,
  menu bar, global shortcuts, and overlay.
- `Sources/EvieShell/OverlayPanelController.swift` owns the transparent floating
  `NSPanel`.
- `Sources/EvieShell/OverlayViewModel.swift` owns one cancellable interaction and
  in-memory conversation context.
- `Sources/EvieShell/Views/` contains the original native-glass capsule, waveform,
  state pill, and artifact-card components inspired by CLUI CC's interaction
  grammar.
- `Scripts/evie-runtime` owns the explicit development setup, verification,
  lifecycle, smoke, and launch commands; `Scripts/test` supplies the current
  Command Line Tools test compatibility flags.

## Defaults and boundaries

| Setting | VS-001 value |
|---|---|
| Server base URL | `http://127.0.0.1:8080/v1` |
| Model ID | `gemma-4-26b-a4b-it` |
| Expected server context | 65,536 tokens |
| Maximum requested completion | 4,096 tokens |
| Network boundary | Loopback only; the adapter rejects non-loopback hosts |
| Conversation storage | Process memory only; lost when Evie exits |
| Prompt/result logging | None |
| Tool execution | None |
| Default local config | `~/Library/Application Support/Evie/config.json` |
| TurboFieldfare revision | `7a99f2a635e3adf7ed0720b882d2edb600f2f0da` |

The context value is a client-side expectation, not a remote control. The server
must be launched with `--max-context 65536`; otherwise its own lower limit wins.
The shell never sends credentials because the upstream loopback server has no
authentication.

Configuration precedence is built-in defaults, local JSON, then supported
environment variables. `EVIE_CONFIG_FILE` may point to another absolute JSON
file. The supported model environment names are documented at the top of
[`.env.example`](../../.env.example); the JSON schema is shown in
[`config/examples/model.example.json`](../../config/examples/model.example.json).
Invalid settings are presented in the overlay and are not silently treated as
valid. Neither source is a credential store.

## Build the shell

From the Evie checkout:

```bash
swift build -Xswiftc -warnings-as-errors
Scripts/test
```

The package targets macOS 15 or later. TurboFieldfare itself currently requires
macOS 26, Metal 4, and Swift/Xcode 26 or newer according to its upstream
documentation. On this exact macOS 27 target Mac, its pinned release server and
repacker built successfully using Apple Command Line Tools without a full Xcode
installation. Treat that as observed local compatibility, not a general supported
prerequisite change.

## Prepare the local Gemma server

From the Evie checkout:

```bash
Scripts/evie-runtime setup
Scripts/evie-runtime doctor
```

`setup` requires at least 25 GiB free, pins the upstream revision, builds the
release products, resumes an interrupted model repack when safe, invokes the
upstream install verifier, and creates the local JSON configuration. Its runtime
layout is:

```text
~/Library/Application Support/Evie/Runtimes/turbo-fieldfare/
~/Library/Application Support/Evie/Models/gemma4.gturbo/
~/Library/Application Support/Evie/State/
~/Library/Application Support/Evie/config.json
~/Library/Logs/Evie/turbo-fieldfare-server.log
```

Nothing in that layout is tracked by Git. The upstream verifier passed 37 installed
files totaling 14,291,915,755 bytes on the target Mac.

After setup returns successfully, the first readiness sequence is:

```bash
Scripts/evie-runtime verify
Scripts/evie-runtime doctor
Scripts/evie-runtime smoke
```

`smoke` starts the server when needed and checks a fixed synthetic non-streaming
response plus an SSE response ending in `[DONE]`. A pass proves basic wiring only;
it is not the Phase 1 16K/32K/64K performance/correctness benchmark.

The 2026-08-04 target run passed. In the recorded shell/server measurement run,
the synthetic non-streaming request completed in 5.393 s and the following SSE
request in 0.882 s. The warmed server physical footprint was 3,215 MB, the native
shell was 18 MB, and both sampled at 0.0% idle CPU on AC power. These short outputs
are not a throughput, quality, long-context, battery, or energy result.

## Launch and interact later

With setup/verification/smoke complete, launch the development executable from the
Evie checkout:

```bash
Scripts/evie-runtime launch
```

The command explicitly starts/checks the loopback server before running the
release shell. It rebuilds that shell only when the release binary is absent or
older than package/source files. Use `Scripts/evie-runtime stop` when the
development server should release its model resources. There is no automatic
launch or background service.

Current interactions:

- `Option-Space` toggles the passive Evie overlay;
- `Option-Shift-Space` opens quick text deliberately;
- `Return` submits non-empty text;
- `Escape` closes quick text without submitting;
- the visible cancel button cancels an active stream;
- cards can expand, close, select text, and copy their completed content;
- the menu-bar item can show Evie, open quick text, or terminate the process.

If the server is absent, unreachable, malformed, or ends without `[DONE]`, the
overlay settles in an error state with a loopback recovery hint. It must never
remain falsely in a thinking state.

## Honest prototype limitations

- This is a SwiftPM development executable, not a signed/notarized `.app` bundle.
- Focus behavior, multiple displays, Spaces, full-screen apps, and shortcut
  conflicts still require `QA-001` on the target Mac.
- The waveform is a reusable data-driven visual component, but receives no audio
  samples in this slice and never displays a false listening state.
- The app does not own model lifecycle, health polling, idle unload, or crash
  recovery. The separate development controller's explicit health/start/stop
  commands do not satisfy those supervisor requirements.
- The direct adapter streams text only. It neither declares nor consumes function
  tools even though TurboFieldfare's server can produce them for a future agent
  loop.
- Conversation context is bounded conservatively by characters because an exact
  Gemma tokenizer is deliberately not linked into the lightweight shell.
- Result-card/history state is not persisted.

## Deferred acceptance (`QA-001`)

When the user chooses to test, record without private prompt bodies:

1. menu-bar launch and clean quit;
2. both global shortcuts and any conflicts;
3. quick-text focus and focus return after `Escape`;
4. streamed response, cancellation, and unavailable-server recovery;
5. bottom anchoring across the built-in display, external displays, Spaces, and
   full-screen apps;
6. Reduce Motion, Reduce Transparency, light/dark mode, and keyboard access;
7. exact OS, Swift, TurboFieldfare revision, server flags, and whether the model

The runtime is ready for the user's manual UI test. The measurements above are
bounded wiring evidence only; no throughput, quality, long-context, battery, or
energy result is claimed. Keep `QA-001` open until the shortcut, focus, Spaces,
display, cancellation, error, and rendered streaming checks are recorded.
